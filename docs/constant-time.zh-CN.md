# 常数时间：统计计时测试

[English](constant-time.md) | 简体中文

`only-crypto` 的常数时间性此前由代码与反汇编论证：没有依赖秘密的分支或内存下标，依赖秘密标量的路径的
release 构建经过反汇编，所有条件分支都已列出（`crates/only-crypto/src/ct.rs` 记录了做法与最近一次结果）。
`tools/ct-dudect` 增加一项独立的黑盒检查：直接测量真实的二进制，看运行时间是否随秘密变化。

## 方法

`ct-dudect` 按 dudect（Reparaz、Balasch、Verbauwhede，“Dude, is my code constant time?”，DATE 2017）
的方法在工具内从头实现（除 `only-crypto` 外没有依赖）：

- **两类输入**：每个目标中，第 0 类为固定秘密（特意选特殊值：标量 1、全零的 X25519 标量或 Ed25519 种子、
  全零的 RSA 摘要、只有最后一字节错误的标签、全零的 limb），第 1 类每次测量都用新的随机秘密。其余输入
  （对端公钥、消息、nonce）两类相同。
- **随机交错**：每次测量的类别由抛硬币决定；两类输入都在计时循环之前按测量顺序构造成独立对象，
  哪一类都不会因留在缓存中而占便宜。
- **计时器**：x86_64 上为 `lfence; rdtsc; lfence`（不变 TSC：固定频率的参考周期），aarch64 上为
  `isb; mrs cntvct_el0`（通用定时器，视机器为 24 MHz 至 1 GHz，较粗：差异体现为计数分布的偏移），
  其它平台用 `std::time::Instant`。每次调用前后各读一次计数器。
- **Welch t 检验**：在线（Welford）比较两类的计时，采用 dudect 的一组检验：全部测量；100 种裁剪，
  只保留低于预热批（不计入）`1 - 0.5^(10(i+1)/100)` 分位数的测量（中断与缓存未命中会拖出长长的上尾，
  可能掩盖细小的偏移）；以及对到类均值距离平方做的二阶检验（1 万次测量之后开始）。统计量取每类至少
  1,000 次测量的检验中最大的 `|t|`。
- **判定**：`|t| > 4.5` 视为泄漏（均值相等时每个检验出现这种情况的概率约为 7·10⁻⁶）。`|t|` 小不是证明：
  只说明在这台机器上、这么多次测量中没有看到差异。
- **自检**：A/A 测试（`sanity-null`，两类完全相同）必须低于 4.5（误报检查）；两个故意泄漏的函数必须被
  检出：提前退出的 256 字节比较（`sanity-leaky-memcmp`）与按指数位分支的平方-乘（`sanity-leaky-modexp`）。
  单元测试（`cargo test -p ct-dudect`）也检查能检出提前退出的比较，并用合成分布检查 t 检验。
- **路径**：每个目标先在硬件路径上运行，再以 `ONLY_CRYPTO_PORTABLE=1` 在可移植代码上运行。没有硬件路径
  的目标（`ct.rs` 原语、`ct_eq`、自检）只在第一遍运行。
- **`--fixed-random X`**：第 0 类改用由种子 X 生成的固定“随机样”秘密而非特殊值，用来区分只与特殊值
  有关的差异和普遍的差异。

## 目标

| 目标 | 第 0 类（固定）对第 1 类（随机） |
|---|---|
| `p256-ecdh` | P-256 ECDH `d·Q`：标量 1 对随机标量，对端固定 |
| `p256-keygen` | P-256 公钥 `d·G`（固定基点梳形表）：标量 1 对随机标量 |
| `p256-sign` | ECDSA P-256 签名（RFC 6979 nonce、`k·G`、`k⁻¹`）：私钥 1 对随机私钥，消息固定 |
| `x25519` | X25519 阶梯：全零标量（clamp 后为 2²⁵⁴）对随机标量，对端固定 |
| `x25519-keygen` | X25519 公钥（Edwards 固定基点）：全零对随机标量 |
| `ed25519-sign` | Ed25519 签名：全零种子对随机种子，消息固定 |
| `x448` | X448 阶梯：全零标量（clamp 后为 2⁴⁴⁷）对随机标量，对端固定（只有可移植实现，只在第一轮运行） |
| `ed448-keygen` | 由种子生成 Ed448 密钥（SHAKE256、带掩码查表的 `[s]B`）：全零对随机种子 |
| `ed448-sign` | Ed448 签名（`[r]B`、模 ℓ 的标量运算）：全零对随机种子，消息固定 |
| `rsa2048-sign-msg` | RSA-2048 PKCS#1 v1.5 签名（CRT、盲化）：全零摘要对随机摘要 |
| `rsa2048-sign-key` | RSA-2048 签名：测试密钥 A 对测试密钥 B（两个固定密钥：每次测量生成一个随机 2048 位密钥太慢） |
| `aes128-gcm-open-tag` | AES-128-GCM 解密，256 字节：只有最后一字节错误的标签对随机标签（标签匹配了多少） |
| `chacha20poly1305-open-tag` | ChaCha20-Poly1305，同上 |
| `hmac-sha256-verify-tag` | `Hmac::verify`：只有最后一字节错误的标签对随机标签 |
| `hmac-sha256-verify-valid` | `Hmac::verify`：有效标签对随机标签（两者都计算完整 MAC 并完整比较） |
| `aes128-gcm-open-valid`、`chacha20poly1305-open-valid` | 有效标签对随机标签；**公开**：调用方本来就知道标签是否通过，两种情况的工作量按设计不同（ChaCha20-Poly1305 只在标签有效后解密；融合的 AES-GCM 在失败时撤销解密）。只报告，不算泄漏 |
| `ct-eq` | `only_crypto::ct_eq`，32 字节：仅最后一字节不同对随机 |
| `ct-word` | `ct.rs` 的 `mask`、`is_zero`、`eq`、`select`，64 个字：全零对随机 |
| `ct-limbs` | `ct.rs` 的 `add_limbs`、`sub_limbs`、`lt_limbs`、`is_zero_limbs`、`assign`、`swap`，2048 位 limb 数组：全零对随机 |

`ct.rs` 是 `only-crypto` 的私有模块；工具通过 `#[path]` 编译同一个源文件，因此测量的是原样的原语，
它们内联进测试工具，正如在 `only-crypto` 中内联进调用方。

## 运行

```sh
cargo build --release -p ct-dudect
taskset -c 2 target/release/ct-dudect --seconds 60 --json hw.json
ONLY_CRYPTO_PORTABLE=1 taskset -c 2 target/release/ct-dudect --seconds 60 --json portable.json
target/release/ct-dudect --list                    # 列出目标
target/release/ct-dudect --seconds 5 p256 x25519   # 只跑一部分（子串匹配）
```

有秘密目标泄漏或自检未检出时退出码为 1。请在安静的机器上运行并把进程绑定到一个核：测试要在机器上
其它一切的噪声中分辨几个周期的差异。繁忙或共享机器上略高于 4.5 的 `|t|`，应当先在安静的机器上更长时间
地重跑，再下结论。

CI 中它是信息性任务 `ct-dudect`（`.github/workflows/ci.yml`，只在发布预发布版本或手动运行时执行；两条路径每个目标 15 秒；任务设置 `continue-on-error: true`，不属于 `ci-ok`）。
表格在任务摘要中，JSON 格式的 t 值在 `ct-dudect` artifact 中。

## 最新结果

2026-11-16，AMD Ryzen 7 7800X3D（Zen 4：AES-NI、VAES、AVX-512、IFMA、BMI2 + ADX），Linux，基准主机已静默
（停止桌面、远程桌面与本地 Kubernetes 集群，电源模式 `performance`），绑定到 2 号核，`rdtsc`，每个目标每条
路径 60 秒或 10⁸ 次测量。运行期间负载均值 1.2–1.6（另一个核上有外部单线程任务）。表中为 102 个检验中最大的

Edwards 部分（X25519 生成密钥、Ed25519）没有汇编，因此 `x25519-keygen` 与 `ed25519-sign` 两列运行的是同一份代码。

解读：

- 测试工具本身有效：A/A 测试在 10⁸ 次测量下仍低于 4.5，两个泄漏函数以上万的 `|t|` 被检出，AEAD 有效与
  无效标签之间公开的差异也如预期被检出（数百个周期：失败路径跳过或撤销解密）。
- RSA（两种幂运算路径、CRT 与盲化）、P-256 ECDH 与生成密钥、X25519、Ed25519 签名、两种 AEAD 与 HMAC 的
  标签校验、`ct_eq` 与 `ct.rs` 原语：两条路径上都未见差异。
- **`x25519-keygen`，仅限全零标量。** 固定类（clamp 后的标量 2²⁵⁴：梳形表 64 个数字中有 63 个为零，累加器
  直到最后一行都保持为单位元）在约 42,000 个参考周期中快 0.1 到 2.5 个周期（≤ 60 ppm），部分运行中显著
  （硬件那一遍最快的 2.6% 测量中 `|t|` 为 40.4，可移植重跑中半数测量上为 11.5），另一些运行中不显著（硬件重跑
  11.8M 次测量为 1.91）。用 `--fixed-random 1`（固定的随机样标量代替特殊值）时两条路径都没有差异（可移植 2.21，
  硬件 1.71，各 11.7M 次）。两条路径上是同一份无分支的可移植代码（`Point::mul_base`：数字重编码、整行掩码选择、
  无数据相关分支的 `add_niels`；`to_montgomery_u`：固定的求逆链；已在反汇编中检查，见 `src/ct.rs`）。只在
  操作数几乎全是单位元常量（limb 为 0 和 1）时出现、且在不同运行间时有时无的一两个周期差异，更像是数据相关的
  功耗或时钟效应（翻转的位少，电压跌落与时钟拉伸少；TSC 以固定频率计数，而核心时钟在变化），而不是代码路径；
  本任务未解释也未修改。真实的 X25519 私钥是 clamp 后的随机位，不会是这个标量。
- **`p256-sign` 可移植路径，处于阈值边缘。** 第一遍 5.26（crop48），用特殊私钥重跑 2.66，用固定随机私钥重跑
  4.91（crop8），硬件路径 2.69；均值差异不到 91,000 个周期中的 5 个。不能稳定复现；与有外部负载的主机上
  数百万次测量时的噪声底一致（重跑期间负载 1.5–3）。nonce 推导（RFC 6979，常数时间范围检查）、梳形表与求逆
  在反汇编中没有依赖秘密的分支。
- 两项发现都未改动代码。下一步是在安静的主机上（并固定核心时钟）对两者做更长时间的测量。

Ed448 与 X448（2026-11-19，ADR-046），同一台主机、同样的方法，经 `quiet.sh`、绑定核心 2、每个目标 60 秒；
这些目标没有硬件路径，跑一遍即覆盖：`x448` 0.79（226,650 次测量）、`ed448-keygen` 1.68（232,300）、
`ed448-sign` 1.34（105,600）、`sanity-null` 2.05（10⁸）。未见差异。
