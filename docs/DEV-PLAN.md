## 1. Repository layout (Cargo workspace)

```text
akio/
├─ Cargo.toml                  # workspace
├─ crates/
│  ├─ akio-sys/               # unsafe syscall wrappers: epoll/kqueue/io_uring/eventfd/sendfile/splice…
│  ├─ akio-buf/               # size-class buffer pool, shared read-only buffers (Bytes-style)
│  ├─ akio-timer/             # hierarchical timer wheel
│  ├─ akio-pool/              # logical thread pool (adaptive, bounded queue, overload policy)
│  ├─ akio-core/              # Engine / Listener / Conn / Handler / Reactor trait
│  ├─ akio-epoll/             # epoll (+kqueue) reactor
│  ├─ akio-uring/             # io_uring reactor
│  ├─ akio-ebpf/              # eBPF acceleration layer (aya), feature-gated
│  ├─ akio-dpdk/              # DPDK reactor + userspace stack, feature-gated
│  ├─ akio-tls/               # own TLS 1.3/1.2, sans-io (kernel TLS opt-in, hardware-first: ADR-067)
│  ├─ akio-http/              # HTTP/1.x, HTTP/2, Router, Context, static files
│  ├─ akio-ws/                # WebSocket
│  ├─ akio-mux/               # several protocols on one port, by sniffing
│  ├─ akio-middleware/        # compress/cors/csrf/etag/limiter/logger/recover/requestid…
│  ├─ akio-arpc/  akio-grpc/  akio-socks/  akio-kcp/  akio-quic/  akio-h3/
│  ├─ akio-media/ akio-webrtc/ akio-bittorrent/   # M7, separate crates
│  └─ akio/                   # facade crate: re-exports + feature flags
├─ examples/                   # echo, http, ws, proxy, blocking-offload …
├─ benches/                    # cross-implementation benchmark suite (incl. scripts against fib)
├─ fuzz/                       # cargo-fuzz targets
├─ tests/                      # integration / interop / chaos tests
└─ docs/                       # ROADMAP, DEV-PLAN, adr/ (architecture decision records)
```

Dependency direction (one way): `sys → buf/timer/pool → core → {epoll,uring,ebpf,dpdk}`; `core → tls → http/ws/…`. Protocol crates depend only on the public traits of `akio-core`, never on a specific backend.

## 2. Public API sketch (settled in the M0 ADRs)

```rust
pub trait Handler: Send + 'static {
    type Conn: Send + 'static;                       // per-connection state, touched only on the owning I/O thread, no Sync needed
    fn on_open(&self, c: &Conn) -> Self::Conn;
    fn on_data(&self, c: &Conn, st: &mut Self::Conn, data: &[u8]);   // non-blocking, inline on the I/O thread
    fn on_close(&self, c: &Conn, st: Self::Conn, err: Option<Error>);
    fn on_hangup(&self, _c: &Conn, _st: &mut Self::Conn) {}          // optional
    fn on_shutdown(&self, _c: &Conn) {}                              // optional
}

#[derive(Clone)] pub struct Conn(Arc<ConnInner>);                    // Send + Sync
impl Conn {
    pub fn send(&self, data: &[u8]) -> Result<()>;
    pub fn send_owned(&self, data: Vec<u8>) -> Result<()>;
    pub fn send_shared(&self, data: SharedBuf) -> Result<()>;
    pub fn send_file(&self, f: &File, off: u64, len: u64) -> Result<()>;
    pub fn cork(&self); pub fn flush(&self) -> Result<()>;
    pub fn close(&self); pub fn close_after_send(&self);
    pub fn hold_reads(&self, hold: bool);
    pub fn notify_output(&self, limit: usize, cb: impl FnOnce(Result<()>) + Send + 'static);
    pub fn spawn_blocking<R: Send + 'static>(
        &self,
        work: impl FnOnce() -> R + Send + 'static,
        done: impl FnOnce(&Conn, &mut H::Conn, R) + Send + 'static,   // returns to the owning I/O thread
    ) -> Result<()>;
    pub fn local_addr(&self) -> SocketAddr; pub fn peer_addr(&self) -> SocketAddr;
}

pub enum Backend { Epoll, IoUring(UringConfig), Dpdk(DpdkConfig) /* Kqueue on macOS only */ }
pub enum Accel   { None, Ebpf(EbpfConfig) }
```
> This is only a sketch: how `Handler::Conn` and the `spawn_blocking` callback obtain `&mut Self::Conn` (generics vs. `dyn Any`) will be decided in M0 by prototyping, picking the form that is friendliest to users and adds no `Sync` bound.

Each task is marked `[ ]`, with the deliverable in parentheses. Each milestone must pass its **DoD (ROADMAP section 4) + a benchmark report + a CHANGELOG entry**.

The fib comparison needs fib to have a plain TCP echo (it has none yet) and a two-machine Linux setup; it moves to the benchmark report in M2. `Conn::spawn_blocking` is M2.

### M2 Multi-backend + logical pool + UDP + TLS (6–8 weeks)
- [x] `akio-pool`: adaptive thread pool (grows on demand to a max, idle threads retire), bounded queue, overload = `Error::Overloaded`, stats
- [x] `Conn::spawn_blocking` + callback re-posted to the I/O thread (skipped if the connection closed or `work` panicked); ordered response slots (`reserve_response`; an unfilled dropped slot closes the connection)
- [x] Slow-callback detection (`Config::slow_callback_threshold`, default 100 ms; `slow_hook` or stderr). Metrics export: done with the Production item in M6 (`Engine::metrics()` as Prometheus text or JSON, akio-http `metrics_handler`)
- [x] `akio-uring`: multishot accept and recv, provided-buffer ring, cooperative/deferred task-run + single-issuer rings, eventfd wake-up, kernel probe (5.19+) with automatic fallback to epoll (`UringConfig::strict` to refuse). Writes use the shared direct-`write`/queue path with a `poll(POLLOUT)` for the backlog
- [x] akio-uring evaluation (2026-11-16): registered files, SEND_ZC, MSG_RING wake-ups, a registered ring fd and ring-based sends were measured and none adopted (rule: same-run +3%, no regression; Linux 7.0, Ryzen 7 7800X3D). SEND_ZC 0.73–0.89x with 10–36% more CPU per request (loopback always copies; re-measure on a NIC); MSG_RING (`IORING_REGISTER_SEND_MSG_RING`) −1.3% to +4.8% on spawn_blocking round trips, noise elsewhere; registered ring fd −3.6% to +0.5%; registered files have nothing to save (no SQE per request in steady state). Ring-based sends (`IORING_OP_SEND`): +1–4% and 2–6% less CPU per request on a bare ring, but they need a redesign of the shared write path (writes come from any thread); decision taken while the user was away: not scheduled, low-priority follow-up. See docs/BENCHMARKS.md "io_uring features evaluation"; harness: akio-uring `eval_server` test, `tools/bench/uring-eval.sh`.
- [x] **Per-listener backend**: several backends in one Engine with independently configured thread groups (tested: epoll + io_uring listeners in one engine); unsupported combinations return clear errors
- [x] UDP (server side): `Listener::udp`; one `Conn` per peer address with the normal `Handler` (`on_data` per datagram, `send` = one datagram, any thread), idle eviction (`Config::udp_idle_timeout`), graceful shutdown that does not wait for a drain, `spawn_blocking` and `close_after_send` work; `SO_REUSEPORT` sockets per thread on Linux (a peer stays on one thread), single thread elsewhere; `recvmmsg` batching on Linux. Tested on macOS and Linux
- [x] UDP client: `Engine::dial_udp` (+ `EngineBuilder::udp_client_threads`, or the threads of a UDP listener): every dialed connection has its own `connect`ed socket, so its own local port; `on_open` runs at once, `on_data` per datagram, idle timeout, `close()`; an ICMP "port unreachable" ends it with `ConnectionRefused`. Tested against a `akio` UDP server (30 concurrent dials = 30 distinct peers), closed port, silent server, cross-thread send
- [x] UDP batching (Linux): `recvmmsg` for server and dialed sockets; the replies of one receive batch leave across peers with `sendmmsg`, equal-size runs to one peer as UDP GSO (probed at runtime, off for good on EIO/EINVAL, `AKIO_UDP_GSO=0`); `Conn::send_segments`, used by akio-quic (up to 10 datagrams per transmit); opt-in GRO (`Config::udp_gro`); `Config::udp_max_peers` with drop counting (`Engine::udp_stats`). Burst sends cost 30–46% less server CPU per datagram, 64 B echo about +19%. Not done: io_uring UDP for per-peer listeners judged not worth it (recvmmsg/sendmmsg already batch); measurements on a real NIC
- [x] Connectionless `DatagramsHandler` (2026-11-21, ADR-065): `Listener::udp(..).serve_datagrams(factory)`, one handler per I/O thread that gets each receive batch as `(peer, &[u8])` and queues replies to any address on `Replies`, sent together when it returns (`sendmmsg` + UDP GSO, the same batching); no peer table, idle timeout or `on_open`/`on_close` (10,000 distinct peers: no peers, no connections, no RSS growth); `DatagramSender` (`Send + Sync + Clone`, also `Engine::datagram_sender`) sends to any address from any thread; reply queue bounded by `max_queued_bytes`, reads pause while replies wait for socket space. epoll, kqueue and io_uring (a ring poll per socket driving the shared `DatagramPort`); not DPDK (`Unsupported`); thread count fixed. Example `udp-dns`, `bench-server udp-dgram`. 64 B echo A/B (gpu51, quiet.sh, 9 rounds): per-peer UDP unchanged (1.02x req/s, 1.00x CPU/request), datagram listener 1.08x (epoll) / 1.09x (io_uring) req/s with 7-8% less server CPU per request (docs/BENCHMARKS.md, "Connectionless UDP").
- [x] `akio-tls`: rustls driven sans-io through a `Transport` layer under `Conn` (server and client, `Tls::server` / `Tls::client` wrap any acceptor; handlers see plaintext), handshake on the I/O thread with application bytes held back until it completes, close_notify on `close_after_send`, `tls_info` (ALPN, SNI, version). Session tickets, SNI certificate selection, client auth, versions: through rustls's own configs. Tested on epoll and io_uring: echo (3 MiB), ALPN/SNI, garbage and untrusted-cert clients, `spawn_blocking` + ordered slots over TLS, `akio` dialing `akio`
- [x] kTLS evaluation (2026-11-16): not adopted. Linux 7.0 software kTLS was slower than akio-tls's own record layer in every case (HTTP/1.1 over TLS, `tools/bench/ktls.sh`: 0.83x at 1 KiB, 0.65x at 16 KiB, 0.40x at 256 KiB, 0.48x for `sendfile` of a 10 MB file vs pread + seal; 1.3–2.5x server CPU per byte; the kernel pushes every 16 KiB record to TCP separately). See docs/BENCHMARKS.md "Kernel TLS (kTLS) evaluation". The offload stays behind akio-tls's `experimental-ktls` feature (test stream, ktls-bench, interop 107/107 vs OpenSSL/Go), not wired into `Tls` or the engine; worth re-measuring on a NIC with TLS offload. Client certificates are configured with akio-tls's own builders (`client_cert`, `client_auth_required` / `client_auth_optional`); TLS 1.3 early data is tracked with QUIC 0-RTT in performance pass 2.
- [x] Kernel TLS in the engine (2026-11-21, ADR-067): `ServerConfigBuilder::ktls` / `ClientConfigBuilder::ktls` (`ktls` feature) move engine connections' record layer into Linux after the handshake on epoll and io_uring, server and client, send and receive directions separately (io_uring stops its multishot recv on a record boundary first). `Ktls::Hardware` (offload only what a TLS-offload NIC does, detected per interface through ethtool, confirmed by the kernel's device counters, refused combinations remembered; no state at all on hosts without such a NIC), `Software`, `SoftwareTx`, `ktls_zerocopy_sendfile`. Control records as ordered `SocketOp`s, `sendfile` under kTLS, TLS 1.3 key updates both ways (own after 2^23 records), `TLS_RX_EXPECT_NO_PAD`, `TlsInfo::ktls_tx/rx`, `akio_tls_ktls_total`. Default build and `Hardware` without a NIC unchanged against main (handshakes and HTTPS within 0.5%, both backends); software kTLS 0.77x on HTTPS. Tests: engine kTLS tests on both backends (20 repeats), curl/openssl 10/10, stream interop 175/175. Not measured: the hardware path (no TLS-offload NIC on the test host).
- [ ] Kernel TLS on a TLS-offload NIC (ADR-067): `Ktls::Hardware` has never run on a NIC with TLS device offload (gpu51 has igc/atlantic only). On a host with one (NVIDIA ConnectX-6 Dx or later; `ethtool -k` shows `tls-hw-tx-offload` / `tls-hw-rx-offload`): check the per-interface detection and the `TlsTxDevice` / `TlsRxDevice` confirmation, the fallback memory for refused combinations, TLS 1.3 key updates on offloaded directions (Linux 6.14+), `ktls_zerocopy_sendfile`; run `tools/bench/ktls-engine.sh` (`hw` against `off` and `base`: HTTPS req/s, large `sendfile`, server CPU per byte) and record the results in docs/BENCHMARKS.md and ADR-067 before making claims about the hardware path.
- [x] Tests: the whole engine/offload/stress suite runs on epoll and on io_uring (`AKIO_TEST_BACKEND=uring`, also in CI on Linux); mixed-backend listeners. Also done: blocking-offload tests (I/O thread not stalled, completion on I/O thread with handler state, pool full, connection closed early, ordering, slot drop, slow callback)
- **Deliverable**: `examples/blocking-offload` (done), backend comparison benchmark report (done: [BENCHMARKS.md](BENCHMARKS.md))

> M2 status: logical pool and io_uring done; all 21 engine/offload/stress tests pass on both backends on Linux (kernel 6.12, Docker), repeated runs without failures. **io_uring vs epoll, same Docker VM, echo, 64 B, client on the same machine:** with 4 server threads / 256 connections both are client-bound (~0.8–1.0M req/s each, no ranking possible); with 1 server thread / 512 connections (server-bound) epoll gave 416k and 492k, io_uring 527k and 538k, i.e. io_uring about 10–25% ahead. The first io_uring implementation, which re-submitted a `PROVIDE_BUFFERS` request per received chunk, reached only ~60% of epoll; returning buffers through a buffer ring (a memory write instead of a submission) removed that gap. Numbers come from a VM shared with the client; treat them as direction, not as a benchmark report. **M2 is complete.** Benchmark report: [BENCHMARKS.md](BENCHMARKS.md). In short: TCP echo in the same class as fib and tokio (ahead of fib everywhere measured, behind tokio by ~15% at 64 connections and 16 KiB, ahead at 512), io_uring not faster than epoll in that setup, the logical pool recovers ~58× over blocking inline.

### Open, not scheduled (2026-11-24)

Leftovers of the performance passes and of the 2026-11-23 rounds that no round has taken up. Each waits on a decision, hardware or a redesign; none blocks 1.0.0.

- [ ] BMI2 code paths in the codecs (akio-brotli, akio-zstd): `#[target_feature(enable = "bmi2")]` on safe functions needs target_feature 1.1, i.e. MSRV 1.86 (the workspace is on 1.85), and the callers then need `unsafe` behind runtime detection. **Waits on the user's decision to raise the MSRV.** Expected gain: the bit readers' shifts (BZHI/SHRX); measure with `tools/codec-bench` against libbrotli/libzstd before adopting.
- [ ] io_uring ring-based sends (`IORING_OP_SEND`, low priority): +1–4% and 2–6% less CPU per request on a bare ring (2026-11-16 evaluation, M2 above), but writes come from any thread, so the shared write path has to be redesigned (sends owned by the ring thread, other threads hand buffers over). Adopt only on the usual rule (same-run +3%, no regression).
- [ ] Kernel TLS on a TLS-offload NIC: waits on a host with such a NIC; see the M2 item above (ADR-067).
- [ ] `akio-bittorrent` `seed_limits_pause` timed out once on a loaded host, cause unknown; the assert now prints both sides' stats. Look at them the next time it fails.
- [ ] `akio-ebpf` `syn_flood_protection_leaves_established_connections_alone` fails on a shared host: the XDP limiter on `lo` counts SYNs from other processes (failed once on gpu51 during the 2026-11-23 run, 3/3 alone). Make it count only its own port, or run it in its own network namespace.

## 4. Engineering rules
- **Data-plane rules**: [docs/rules.md](rules.md) (never block an I/O thread, bounded bodies and queues, linked backpressure, timeouts and safe-default limits, build-time work on the hot path, verification sized to the change); defaults in ADR-009.
- CI (decided by the user, 2026-11-16): GitHub Actions runs only when a pre-release is published or by hand; ordinary commits, pushes and pull requests do not trigger it. Every change is verified locally before it is pushed: macOS, Linux arm64 in Docker (epoll and `AKIO_TEST_BACKEND=uring`), and natively on x86_64 Linux for the x86 assembly, real io_uring and benchmarks.
- **Branches/commits**: `main` stays releasable; feature branches + PRs; Conventional Commits.
- **Code**: `#![forbid(unsafe_code)]` by default; unsafe allowed only in `akio-sys`, the backends and `akio-buf`, each with a `// SAFETY:` comment.
- **Test pyramid**: unit → loom/miri → integration/interop → chaos → benchmark; new features need tests and protocol parsers need fuzz targets.
- **ADRs**: any decision affecting the public API, threading/lock model or dependencies is first written as `docs/adr/NNN-*.md`.
- **Docs**: every crate has crate-level docs and runnable doctests; READMEs stay bilingual (as in fib), `X.md` in English and `X.zh-CN.md` in Chinese.
- **Performance**: a PR touching hot paths attaches before/after benchmarks; nightly benchmarks compare against historical baselines.
