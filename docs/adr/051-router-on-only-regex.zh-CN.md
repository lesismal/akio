# ADR-051：路由约束改用 `only-regex`

[English](051-router-on-only-regex.md) | 简体中文

状态：已接受（2026-11-19）

## 背景

工作区里有两个正则引擎。`only_http::re`（DEV-PLAN 第 A 波，ADR-007）负责路由约束（`{id:[0-9]+}`）：
Thompson NFA，最多 64 条消耗指令的程序用位并行模拟，更大的用 Pike VM；整段匹配，`\d \w \s` 为 ASCII，
不支持标志，除 `^ $` 外不支持断言。`only-regex`（ADR-047）是 only-log 消息过滤背后的引擎：Unicode 字符类、
`(?i)`、`\b`、非锚定查找，编译时构建 DFA。ADR-047 把路由迁移到 `only-regex` 留作后续工作，因为两者在锚定
方式和 `\d` 的含义上不同，任何一点都会改变哪些路由能匹配。

两个引擎意味着要让两个解析器与 `regex` crate 保持一致，要维护两个模糊测试目标，也有两份 bug。
`only_http::re` 是 `#[doc(hidden)]` 的，不在 `api/only-http.txt` 中：它不是公共 API，移除它不需要走弃用
流程（docs/deprecation.md 针对的是公共条目）。

## 决策

1. **`only-regex` 新增 `RegexBuilder`**，有两个选项（`Regex::new(p)` 即 `RegexBuilder::new(p).build()`，
   行为不变）：
   - `whole_text(true)`：模式要么匹配整段文本，要么不匹配，相当于写成 `\A(?:pattern)\z`。编译器在程序
     前后加上这两个断言；纯字面模式用 `==` 比较，而不是 `str::contains`。
   - `ascii_classes(true)`：`\d \w \s` 及其取反为 `[0-9]`、`[0-9A-Za-z_]` 与 `[\t\n\x0B\x0C\r ]`，
     `\b \B` 只把 ASCII 字符视为单词字符（非 ASCII 字符不是单词字符）。字面量、字符类、`.` 与 `(?i)`
     保持 Unicode 含义。
   - `Regex` 的相等比较现在也比较选项。
2. **路由器用这两个选项编译每个约束**（`router::Matcher`），正则段与部分段中都是如此。优先级、回溯、
   花括号处理和注册时的 panic 都不变：变的只是背后的匹配器。
3. **可接受的模式：原有集合，加上有文档记录的超集，减去重复组名。** 旧引擎接受的每个模式匹配的段完全
   相同。路由器现在还接受 `only-regex` 支持而旧引擎拒绝的内容：标志 `(?i) (?m) (?s) (?U)`（可取反、可限定
   范围）、`\A \z \b \B`、Unicode 或含 `.`、`[`、`]` 的组名，以及 10 000 到 20 000 条指令的程序。唯一的收紧：
   两个同名分组（`(?P<a>x)|(?P<a>y)`）在注册时被拒绝，与 `regex` crate 一致（旧引擎声称是 `regex` 的子集，
   却漏掉了这种情况；由于不做捕获，组名从来没有任何作用）。
4. **旧引擎保留为测试参照。** `only_http::re` 从 API 和普通构建中移除；源码原样保存为 `src/legacy_re.rs`，
   只在测试与 `fuzzing` feature 下编译，让下面的差分检查一直运行。
5. **`only-regex` 的 DFA 快速路径。** `Regex::is_match` 先在一个紧凑循环里运行预先构建的 DFA（每字符一次
   类查找和一次表读取，没有查找状态），只有遇到 DFA 未构建的转移时才回退到完整查找。每个 DFA 状态行增加
   一个文本结束项，结束查找时不再需要做除法求状态号。only-log 的消息过滤也因此变快。

## 验证

- 差分测试（`legacy_re::differential`，随 `cargo test` 运行）：仓库测试、示例、文档和基准中的所有正则路由
  模式，旧引擎自身单元测试中的模式（接受的和拒绝的），3 000 个生成的模式（字面量、Perl 类、字符类、转义、
  `.`、`^ $`、分组、选择、贪婪与惰性计数重复），每个约 30 个主体（由模式生成的文本、对其做单字符变异的
  文本，以及由 ASCII、控制字符与非 ASCII 数字、字母和空白组成的随机文本），以及 20 000 个随机语法片段。
  对每个模式：接受/拒绝的判断一致（第 3 点除外），每个主体的结果一致。关掉任一选项，测试都会失败。
- `regex_match` 模糊测试目标现在对模糊输入做同样的检查（旧引擎对比路由器的匹配器），然后将匹配器与 `regex`
  crate 对比（`^(?:pattern)$`；模式含 Perl 类或单词边界时只比较 ASCII 主体）。gpu51：4 个 worker 运行 997 秒，83.5 万次执行，语料从 11 增至 2 607 条，无发现。
- 路由器测试覆盖 ASCII `\d` 与 `\b`、`(?i)` 和重复组名 panic；`only-regex` 单元测试覆盖两个选项（DFA、NFA
  与流式匹配结果一致）。

## 影响

- 开销（gpu51，CPU 2，在 `quiet.sh` 下同次运行 A/B，基线为本次改动之前的 main）：`examples/router-bench.rs`，
  每次查找的纳秒数，取 10 轮中 6 个安静轮次的中位数（另外 4 轮主机对两个二进制同样慢了 1.7 倍，比值不变）：
  带 `{id:[0-9]+}` / `{number:[0-9]+}` 的 GitHub 路由表 28.1 → 28.1，新增的 8 条多样约束路由表（计数重复、
  选择、字符类、部分段）46.0 → 42.0，普通表与部分段表 27.2 → 27.1、28.7 → 28.6；全部 0 次分配。单看引擎
  （`tools/codec-bench regex`）：7 位数字上的 `[0-9]+` 8.5 → 5.7 ns，`\d{4}-\d{2}-\d{2}` 11.9 → 7.6，14 个字符
  上的 `[a-z0-9_-]{3,16}` 17.6 → 10.6，`(?:v[0-9]+|latest)` 7.5 → 5.4。编译约束会在注册时构建 DFA：
  7–13 µs，原先 2.1 µs，每条路由只发生一次。only-log 的消息过滤也因快速路径快了几个百分点
  （`codec-bench logregex`）。
- 公共 API：`only-regex`（内部层级）新增 `RegexBuilder`（`new`、`whole_text`、`ascii_classes`、`build`）。
  only-http 的公共 API 不变；它现在直接依赖 `only-regex`（此前已经通过 only-log 间接依赖，依赖图不变）。
- 只剩一个引擎：语法修复和新特性只需做一次。旧引擎的 1 000 行代码冻结保留，只要差分检查值得维护。
- `tools/codec-bench regex` 测量带路由器选项的 `only-regex` 与 `regex` 的对比。
