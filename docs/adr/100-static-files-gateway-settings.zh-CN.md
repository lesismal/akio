# ADR-100：面向网关的静态文件：调用者给出的路径、按 q 值选择压缩副本、候选路径、目录列表

[English](100-static-files-gateway-settings.md) | 简体中文

状态：已采纳（2026-11-24）

## 背景

akit 是基于 akio 的反向代理和网关，它的 `static` handler 用 `akio_http::files::Files` 提供文件，必须像 fit（akit
所重建的网关）那样应答。akit 的需求 A13、A16、A17 和 A18 列出了 `Files` 做不到的四件事：

- **A13。** `Files` 从路由参数 `path`（只有 akio 自己的 `Router` 会设置）或请求目标取路径。按自己的路径路由的
  调用者（去掉前缀或去掉点段）无法把那个路径交给它。
- **A16。** 文件的 `.br`、`.zst` 或 `.gz` 副本提供给 `br`、`zstd`、`gzip` 中第一个出现在 `Accept-Encoding` 里的
  编码，不看 q 值。`br;q=0` 得到客户端拒绝的 `br` 副本；`*` 得不到副本；`GZIP` 和 `gzip ;q=1` 也得不到。副本既不
  能限定为某些编码，也不能关闭，并且总是发送 `Vary: Accept-Encoding`。
- **A17。** 没有 `try_files`：依次尝试候选路径，提供第一个存在的（单页应用用 `["{path}", "{path}/", "/index.html"]`）。
  `Files` 在磁盘池上自己答 404，调用者既不能尝试另一个路径，也无法在不在 I/O 线程上做磁盘工作的情况下得知路径不
  存在。
- **A18。** 没有目录列表：没有索引文件的目录答 404，而且是在磁盘池上答，调用者无法在那里列出目录。

约束：API 只增不改；默认行为不变，只有副本的选择现在遵循 RFC 9110；I/O 线程上不碰磁盘；新增的内存都有界；缓存
命中的路径不变慢。

## 决定

全部在 `akio-http` 的 `files.rs` 中。

- **`Files::serve(&self, ctx, path)`**（A13）：以给定路径执行 `Service::call` 的逻辑（路径按发送时的样子，百分号
  编码）。路径像以前一样解码和检查：拒绝 `..`、NUL、`\` 和 `:` 段。`call` 现在用路由参数或请求路径调用它。
- **按 q 值选择副本**（A16）：`pick` 按所有 `Accept-Encoding` 字段中的 q 值（RFC 9110 第 12.5.3 节）给磁盘上的副本
  排序：编码自身的 q 值，否则 `*` 的，0 表示拒绝。名字不区分大小写比较，并去掉空白；无法解析或不在 0 到 1 之间的
  q 值按 1 计，与 Go 写的 fit 一致。相同时取 `Files::twins` 顺序中靠前的。
  - `Files::twins(&[&str])` 设置查找哪些编码以及这个顺序。默认 `br`、`zstd`、`gzip`，与以前相同；未知名字和重复的
    名字被忽略。
  - 为空时不查找副本，也不发送 `Vary`。
  - 命中时的开销：没有副本的文件为零。否则每找到一个配置的副本就解析一次字段。
- **`Files::try_paths(&[&str])`**（A17）：候选模板，`{path}` 代表解码后、以 `/` 开头的请求路径。
  - 候选在磁盘池上依次解析。以 `/` 结尾的候选表示目录，由它的索引文件或目录列表提供。
  - 以下候选被跳过：指向不带斜杠的目录、带斜杠的文件、既不是普通文件也不是目录的东西、通不过上述检查的路径，或被
    `hide` 隐藏的路径。都没有时答 404。目录从不重定向。
  - 请求路径解析到的文件保存在一个最多 4096 条的映射中（满时清空），在 `check_interval` 内、且文件自己的条目仍新鲜
    时可信。这样最近解析过的路径的请求就像普通命中一样在 I/O 线程上应答。
  - **`Files::hide(f)`**：对解码后路径的测试。返回 true 时请求的路径答 404，候选被跳过（fit 的 dotfiles）。它必须
    是 `RefUnwindSafe`，这样 `Files` 仍是 `UnwindSafe`。
- **`Files::list_directories(max_entries)`**（A18，默认关闭）：带尾部斜杠请求（或由以 `/` 结尾的 `try_paths` 候选
  到达）、没有索引文件的目录，每次请求都在磁盘池上列出。
  - 最多读取 `max_entries` 项；多读一项用来判断页面是否要说明还有更多。先去掉以点开头的名字，再把目录排在前面，
    每组按名字排序。
  - 页面是一个 HTML 表格，名字经过 HTML 转义，链接是相对的、百分号转义的单个段，带大小和 UTC 修改时间。发送时带
    `Content-Type: text/html; charset=utf-8` 和 `Cache-Control: no-cache`。
  - 页面与 fit 的逐字节相同。

未采用：

- 公开设置路由参数的方法：任何服务都能借此改写路由器匹配的结果，只为一个用途。
- 让调用者用响应过滤器截获 `Files` 的 404：过滤器在发送响应的线程上运行，这不能作为做磁盘工作的约定。
- 缓存目录列表：fit 不缓存，列表受 `max_entries` 限制，而缓存的列表需要监视它的目录。

## 影响

- akit 的 `static` handler 可以提供 `strip_prefix` 和规范路径、fit 的 `precompressed` 选择、`try_files` 和
  `browse`。akit 的 A14 和 A15 中的其他差距仍然存在。
- 以前发送 `br;q=0` 却得到 `br` 的客户端现在得到原文件；发送 `*` 的客户端现在得到首选的副本。两者都遵循
  RFC 9110；CHANGELOG 把它列在 Changed 下。
- 测试：`features.rs`（按 q 值选择副本、配置的副本和不要副本，来自池和来自缓存；去掉前缀的 `serve` 和被拒绝的
  越界路径；有和没有检查间隔的 `try_paths`、被隐藏和不安全的候选、在磁盘上变化的解析结果、5000 个不同路径；目录
  列表、转义、顺序、上限、HEAD 以及经由 `try_paths` 的列表）。`files` 单元测试覆盖 q 值、转义和日期。
