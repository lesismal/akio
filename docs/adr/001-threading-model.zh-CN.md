# ADR-001：线程模型

[English](001-threading-model.md) | 简体中文

状态：已采纳（2026-11-13）

## 决定

采用 thread-per-core：每个连接在整个生命周期内只属于一个 I/O 线程。新连接由 `SO_REUSEPORT` 分配到各线程（可选 eBPF 调度，见 ADR-006），回调直接在该线程内联执行。

## 影响

- Handler 状态无需加锁、无需 `Sync`；连接内的事件顺序天然保证。
- 慢回调会拖慢同线程的其它连接。缓解：文档明确“回调不得阻塞”、显式 `spawn_blocking`（ADR-002/003）、可配置阈值的慢回调检测。
- 与 fib（每一轮由任意空闲 worker 执行）不同，负载均衡按连接而不是按轮次，热点连接无法迁移。此取舍已接受。

## 更新（2026-11-23，ADR-100）

连接所在的线程现在在 accept 时选择，而不只由内核决定：线程接受一个连接时，若它持有的连接比本监听器最少的线程多出 `2 + min / 32` 以上，就在读取任何数据之前把连接交给那个线程（`Balance::LeastConnections`，默认；`Balance::Kernel` 保留内核的选择）。`on_open` 及之后的所有回调都在接收线程上运行，因此连接仍然终生属于一个线程。
