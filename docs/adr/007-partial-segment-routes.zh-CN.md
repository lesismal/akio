# ADR-007：段内部分匹配的路由模式

[English](007-partial-segment-routes.md) | 简体中文

状态：已采纳（2026-11-16）

## 背景

`only_http::Router` 过去只匹配整段：静态段、`{id:re}`、`:id`/`{id}`、`*rest`。`/{name}.txt`、
`/v{version}/x`、`/{owner}/{repo}.git` 这类路由只能先用参数接住、再在 handler 里检查。支持它们会改变
模式语法和匹配顺序，两者都是 `Router` 对外行为的一部分。

## 决定

1. **语法。** 一个段中同时有字面文本和 `{…}` 组时称为*部分段*：`{name}.txt`、
   `v{major:[0-9]+}.{minor}`、`pre-{mid}-post`。组写作 `{name}` 或 `{name:regexp}`；组内花括号可嵌套
   （`\d{4}`），反斜杠转义下一个字符，`[…]` 字符类中的花括号按字面处理。通配符不能与其他内容同段，
   两个参数之间必须有字面文本，花括号不配对时在注册时 panic，与其他路由错误一致。
2. **匹配：线性，段内不回溯。** 段首的字面文本和段尾的字面文本分别在段首、段尾匹配。中间每个参数非空，
   并在其后字面文本第一次出现处结束；正则参数还必须匹配其整个取值。因此 `{name}.txt` 匹配 `a.b.txt`
   时 `name = a.b`，`{name}.{ext}` 匹配 `a.b.c` 时 `name = a`、`ext = b.c`（与 chi 相同）。不会尝试其他
   切分位置：无论模式如何，查找时间都与路径长度成线性。
3. **优先级。** 部分段位于静态段和整段正则之间：**静态 > 部分段 > 正则 > 参数 > 通配符**，不同种类之间
   照旧回溯。部分段带有字面文本，比整段参数更具体；排在正则之前，是因为路由表里的正则多数很宽
   （`[0-9]+`、`.+`）。部分段之间，字面文本多的先试（`{name}.tar.gz` 先于 `{name}.gz`），其次按注册
   顺序。形状相同的模式（`{a}.txt` 与 `{b}.txt`）是同一个节点，参数名不同则 panic。
4. **不分配内存。** 匹配时与其他种类一样只记录参数的字节区间。

## 影响

- 只使用旧种类的路由表匹配结果完全不变（路由基准不变，原有测试全部通过）。
- 含 `{…}` 组的静态段现在是模式，花括号不配对的会 panic。无法配平花括号的整段 `{…}`（正则在少见
  位置含未转义的花括号）保持原有含义。
- 需要其他切分方式（按最后一个 `.` 而非第一个）的路由，请用整段正则参数，或在 handler 里检查。
