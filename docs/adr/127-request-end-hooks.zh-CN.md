# ADR-127：得知请求的结束：响应完整发出，或客户端离开

[English](127-request-end-hooks.md) | 简体中文

状态：已采纳（2026-11-25）

## 背景

fit 的 `concurrency_limit` 把一个请求算作进行中，直到其响应发出或其客户端离开（fib 的
`OnFinish` 和 `OnCancel`）；它的访问日志和指标把流式响应的耗时算到其结束；ADR-125 的
Proxy-Wasm 宿主在请求结束后调用插件的 done、log 和 delete 回调。akio-http 对服务两者都不告知
（akit 的需求 A48）：

- 唯一的钩子是响应过滤器，它在响应头发出时运行：流式响应（`stream_response`，akit 的代理对
  所有超过 64 KiB 的消息体都使用它）在其消息体仍在发出时就离开了限制。
- `on_gone`（ADR-108）能得知客户端离开，但只容纳一个回调：限制和取消上游请求的代理不能同时
  使用它。
- 被服务器放弃的请求（未完成就被丢弃的 `Detached` 或 `BodyStream`）什么也不告知。

## 决定

`Context::on_end(f: impl FnOnce(End) + Send + 'static) -> bool` 和 `Detached::on_end(f)`，
以及 `#[non_exhaustive] enum End { Sent, Gone }`。无论注册之后请求如何（就地回答、分离、流式、
挂起、升级、在池上运行），每个 `f` 恰好运行一次：

- `End::Sent`：响应已完整交给连接：完整响应发出时（HTTP/1 响应按流水线顺序排入其连接），流式
  响应在 `BodyStream::finish` 排入最后一个字节时，过滤器编码的文件消息体（ADR-124）在其泵完成
  时，升级在其 `101`（或 HTTP/2、HTTP/3 的 `200`）发出或连接被接管（`upgrade_raw`）时。
- `End::Gone`：请求在此之前结束：客户端离开，按 `on_gone` 的判断（连接关闭、HTTP/1 的 EOF、
  HTTP/2 或 HTTP/3 流被重置或停止），在分离等待或流式发送时都能得知；或服务器放弃了响应（未
  完成就被丢弃的 `Detached` 或 `BodyStream`、未回答就被丢弃的上下文）。

多个钩子按添加顺序运行，在结束请求的线程上运行（发出或完成响应的线程，客户端离开时为连接的
I/O 线程）。结束之后添加的钩子立即以该结果运行。仅当响应已被取走（分离、流式、升级）且此前没有
注册任何钩子时，`Context::on_end` 返回 `false` 并丢弃未运行的 `f`：此时已无法从上下文跟踪该
请求；应在此之前注册，或在 `Detached` 上注册。

**实现。** 注册了 `on_end` 或 `on_gone` 的请求得到一个 `Hooks`（一个 `Arc`，其中的互斥锁保存
`on_gone` 回调、结束钩子以及请求如何结束），由上下文和取走其响应者（`Detached`、`BodyStream`）
共享，后者各自把它放在一个 `EndGuard` 中：响应发出时以 `Sent` 结束，先被丢弃时以 `Gone` 结束。
传输层通过其唯一的对端离开回调（ADR-108）以弱引用持有它，只注册一次：客户端离开时运行
`on_gone` 回调并以 `Gone` 结束请求。`on_gone` 保持原意（一个回调，最后设置的那个；响应发出后
丢弃；客户端离开后才注册则立即运行），现在与结束钩子并存，而不再占用传输层的唯一槽位。两者都不
注册的请求不付出任何代价：没有分配，`respond` 只移动一个空守卫。

也考虑过不用装箱闭包的形式（如 A29 的观察者）：钩子按请求注册，中间件的状态属于它自己；每个
钩子一次装箱，是组合多个钩子（限制、日志、插件）的代价。

## 影响

- akit 的 `concurrency_limit` 在 `on_end` 时归还请求的名额，而不是在响应头发出时；其访问日志、
  指标和追踪把流式响应的耗时算到其结束；ADR-125 的宿主（里程碑 W6）由它调用插件的 done、log 和
  delete 回调。
- `Context` 实现了 `Drop`（未回答的上下文会结束其钩子）；`suspend` 把钩子带到恢复后的上下文。

## 测试

`crates/akio-http/tests/end_hooks.rs`（HTTP/1.1 和 HTTP/2，epoll 和 io_uring）：完整响应、两个
钩子按顺序运行、从另一线程回答的分离请求（旁边的 `on_gone` 不触发）、在完成时而不是响应头时
结束的流式响应、挂起的请求、服务器自己的 500、响应之后添加的钩子（立即运行）以及无钩子分离之后
添加（被拒绝）；客户端离开的分离请求（在放下 `Detached` 之前就得知）、未完成的流（先 `on_gone`
后 `Gone`，各一次）、被丢弃的 `Detached`、被重置的 HTTP/2 流和关闭的连接；客户端离开之后添加的
钩子，在调用者线程上立即运行。`crates/akio-h3/tests/end_hooks.rs`：同样的场景走 HTTP/3。ADR-108
的 `on_gone` 测试不变地通过。
